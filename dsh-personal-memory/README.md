# dsh-personal-memory

一个 DSH 插件，两件事：

1. **每轮自动召回** —— 在模型开始思考之前，把工作区里和这句话最接近的既往笔记，作为一条「不是用户发言」的召回块注入上下文。
2. **一个整页的个人记忆面板** —— 侧栏点进去，左边是目录，右边是正文。`personal/` 是懂过的东西（个人记忆），`memory/` 是走过的日子（时间长河）。

它不新建存储，也不复制笔记。文件始终是唯一真相源；索引只是可重建的检索层。

```
                       ┌──────────── dsh-personal-memory ────────────┐
  Agent 每一步 ──▶ pre-step 钩子 ──▶ ctx-server(17878) ──▶ 召回块    │
                       │                                          │
  GUI 侧栏 ──▶ 整页面板 ──▶ /personal-memory/* 路由 ──▶ 直接读工作区文件 │
                       └──────────────────────────────────────────────┘
```

## 六套自检

| 自检 | 跑的是什么 | 证明什么 |
|---|---|---|
| `node smoke.mjs` | 假 ctx 跑 `pre-step` 召回 | 注入块、去重、阈值、子树跳过、混合补漏 |
| `node smoke-client.mjs` | 假模块加载器加载 client 半 | 侧栏入口 + 整页面板 + 设置分区的注册形状 |
| `node smoke-panel.mjs` | 沙箱工作区（`mkdtemp`）+ 全部路由 | 每条路由的成功/拒绝路径（含 403/409/400） |
| `node smoke-render.mjs` | 离线渲染整棵组件树（`harness.mjs`） | 数据层与渲染层字段对得上、点下去真的回调 |
| `node check-props.mjs` | 静态解析 `client.js` | 组件读的 `initialXxx`，`App` 都传了 |
| `node smoke-live.mjs [端口]` | **打正在运行的宿主** | 代码真的装进去了、路由真的活着、越界真的 403 |

前五套离线跑（不需要 GUI），最后一套只在 GUI 开着时有意义——它抓的是「本地全绿但没装上」这一类问题，也真的抓到过一次：`/doc` 的越界路径返回 500 而不是 403（本地断言当时写的就是 500，等于把 bug 冻进了测试）。

## 两个视图，一句话

| 视图 | 读的是什么 | 回答什么问题 |
|---|---|---|
| **个人记忆**（`personal/`） | 31 篇认知笔记：关于我、工作、健康、投资、学习 | 「我上次是怎么想的？」 |
| **时间长河**（`memory/`） | 每天的日记（`产出 / 判断 / 未完成 / 备忘`） | 「那天到底发生了什么？」 |
| **未完成**（`memory/` 里所有 `- [ ]`） | 从日记里抽出来的待办，带「晾了多少天」 | 「我欠自己什么？」 |

两者互相指认：读一篇 `personal/` 笔记时，阅读器底部会用它的标题+摘要去检索，列出「相关笔记」；读一篇日记时，同理。点击即跳。

## 面板里有什么

六个页签，都在同一页里：

- **今天**（默认首屏）—— 打开就能用的那一页：四张数字卡（今天日期/今天写了几条/今天未完成/日记天数），「今天该做的」**分成两拨**：**今天新加的**（今天日记里的 `- [ ]`，最多 4 条）和**挂着没做的**（更早的，补满 8 条），都带「几天前」、能直接勾或挪明天。标题右侧有**排序切换**：「今天新加的在前」（默认，适合推进）/「最久没动的在前」（适合清账），选择写进 `state.json` 的 `ui.todoSort`，刷新后还是这个顺序。为什么分：混排按日期排，今天刚想起来的事会沉到最后，首屏反而看不见今天新增，「今天这篇」（今天的日记预览 + 打开 / 没写时给「写一条」），**「往前两天」**（昨天 / 前天的日记：日期 + 星期 + 条目数 + **欠几件** + 一句摘要，点开就是那一天；窄屏下这两张换成横向滑动卡片，一屏看得见一张半，右边露一角就是「还能滑」）、「最近改过」。列表被截断时**就地展开**：「就地展开剩下的 28 条」把其余条目直接摊在这一页（再点收起回 8 条），旁边另给「去未完成页 →」——展开是为了不打断「我现在在哪」，跳页是另一种需要，两个动作分开。
- **个人记忆** —— 按目录分组的笔记列表（组内 `index` 优先、其余按修改时间倒序），顶部有标题筛选。**星标过的笔记单独置顶成一组**，不用每次翻目录。「关于我 / 工作 / 健康 / 投资 / 学习 / 日记」各自折叠。右侧阅读器显示正文和标题目录（可点击跳转），顶部 chip 显示 `更新:` / `来源:` / 字数 / 行数。
- **时间长河** —— 顶部先是**一年 12 格的月份地图**：每格写月份 + 记了几天，颜色深浅按「这个月记得最多」的比例算（全空只留描边），回答「今年哪几个月我在认真过日子」；点一格会展开那个月并滚到它的位置（没有 DOM 的环境直接跳过），跨年不做全景、只看最新一篇所在的那一年，因为「去年」的密度和今天的问题通常无关。下面是按月分组的竖轴时间线，**月份头可折叠**（折叠偏好存在 `.dsh/personal-memory/state.json`，刷新后还记得），还带这个月的三件事：记了几天 · 合计多少条 · 空了几格（只算已经过去的日子，未来的不算）。每天一行：日期、星期、未完成徽标、条目数、一句预览。点开就是那天的完整日记。**读过的地方会记一条阅读路径**：从左栏一路点进好几篇之后，正文头部有「↩ 上一处」，或者按 `Alt+←` 退回上一篇（只记路径、不记滚动位置，最多 20 步；同一篇重复点开不算新的一步）。浏览器里 `Alt+←` 是后退，面板借同一个手势。**窄屏上回退按钮只留一个 `↩` 箭头**（文字进 `title`），给标题和星标/编辑腾地方；「返回列表」是另一件事（列表 ↔ 正文），窄屏仍然单独一行，不要和回退混成一个按钮。**每天行下还会显示「改过：xxx · yyy」**——那天除了写日记，在 `personal/` `project/` 里还动过哪几篇（按文件 mtime 折成本地日期，最多列 3 篇 + 余数；mtime 是 UTC，不能直接切前 10 位，否则本地凌晨的记录会算到前一天）。日记行说「那天想什么」，改过行说「那天动了什么」。**没写的日子会显式标出「N 天没记」**：两天挨在一起和中间空了三天，是两种不同的事实，时间轴不该假装连续。
- **未完成**（`memory/` 里所有 `- [ ]` 的合并视图）—— 默认按「欠了多久」分三档：**今天还没做 / 这一周欠的 / 更早（一周以上）**，每档可折叠、档头带条数；行上带日期，超过一周的补一个「N 天」徽标。顶部还能按「全部 / 今天的 / 3 天以上 / 一周以上」筛（筛了就不再分档 —— 找一个窗口时不需要三层结构）。这是全工作区唯一一处能看到所有未完成事项的地方。**每条前面的方块可以直接点**：点一下就把那天的日记里这一行改成 `- [x]`，面板里的数字同步减少；勾错了再点一次取消。**每行还有一个「?」**：点开就地展开那天日记的开头，勾之前先看一眼「这条是哪天为什么加的」，不用跳页；底部一个「打开那天 →」才跳。**每行还带一个 ⌛ 标记（标上时记时间戳，等了 3 天以上会在页顶被问一句「还在等吗」——「继续等」重置计时、「变成行动」先问一句下一步（回车存下，显示在待办正文下面一行；点这句话会打开那篇笔记、进编辑态、光标落在待办原句上）再清标记）（点一下循环：等行情 → 等人回 → 等自己决定 → 清除，key 是正文摘要所以改期后标记跟着走），配合顶部「只看在等的」把「我只能等」和「我能推进」分开；每行右边还有「明天」「周一」两个改期按钮（`to: 'tomorrow' | 'monday'`，日期由宿主算：周一按钮当天就是周一也会顺延，不会原地不动）**：今天不做不等于做完了，点它会把这条从当天日记里删掉、再在明天日记的「未完成」里落一条同文的（先写目标再删源 —— 中途失败最多多一条，不会丢字）。
- **检索** —— 空输入时列「最近查过」，并且**存的是「查询 + 范围 + 时间窗」的组合**而不是一句裸文本：chip 上直接写着 `止损线 · 个人/长河 · 7 天内`，点一下不只填回那句话，还把范围和天窗一起恢复、立刻重跑。同一句话换了筛选条件算两条历史（换了条件就是另一个问题）；只记人手输入的查询，不记拿正文当 query 的内部检索。**向量 + 词面混合**：向量召回（contextdb）之外再扫一遍标题/路径/全文，两边合并、同路径的去重并标「词面」。这样「止损线怎么定的」走语义，「600519」「17878」这种精确 token 走字面，各管一段；ctx-server 挂了也还能用词面层检索（`mode: keyword-only`）。范围可勾选 `personal / memory / project`，也可以只找「不限时间 / 7 天内 / 30 天内」改过的笔记（按磁盘 mtime 过滤，向量与词面两路都过一遍）；命中显示分数条、所在小节、摘要，以及「改于几时」（今天 / 3 天前 …，没有 mtime 就干脆不显示）—— 时间过滤开着却看不出哪条是新的，等于白开。**命中一行点开时不只是打开那篇，还会滚到它所在的那一节**（行上显示的 `› 小节` 就是落点；标题比对去掉了 `《》` 与空白，匹配不上就停在文首）。
- **召回** —— 运行状态灯、累计召回/命中统计，以及**召回命中率**卡：近 7 天注入的每一篇里，有多少后来真的被打开过（`used / injected` · 百分比）。没有样本时显示「—」而不是 0%，因为「召回了但都没用」和「根本没召回」是两件必须分得开的事。这张卡是判断阈值该不该调的唯一凭据、手动「试一下」召回、重建索引、当前配置只读表。**摘录长度按来源分**：字面命中（`via: keyword`）的句子是「他真写过的话」，保留 `excerptChars` 全长；语义命中只要够认出「讲的是哪件事」，用 `semanticSnippetRatio`（默认 0.55）压缩。真工作区实测（`止损线怎么定`、`topK: 8`）：1204 字 → 与旧行为 2531 字相比，同样 8 篇只占 2155 字（`ratio: 0.4` 时 1882 字）。省下的是上下文，不是信息——被砍掉的那半句本来就是「话题相邻」的部分。`/test` 用同一套规则，所以面板里看到的字数和真实注入的一致。

**注入块标出来源**：召回块每条标题行后面带 `·[原话]`（正文里真的出现过这几个字）或 `·[原话+语义]`（两边都命中），纯语义的不标。这样在会话里读到召回内容时，能一眼分辨「这是我写过的话」还是「语义猜的」，避免被错误联想带跑。另外词面命中的摘录不再以 `# 标题` 开头——注入块里已经有《标题》了。

**召回也走混合，并记下来源**：`pre-step` 的自动召回原来只吃向量（`mode` 配置形同虚设），查「17878」「PMKWTOKEN」这类精确词会漏。现在向量挑完之后，预算还有就用词面层补最多几篇（`max(topK,quota)` 上限内），每条记得住 `via: 'vector' | 'keyword' | 'both'`；面板的「最近召回」展开后给「词面 / 都中」徽标——能直接看出这篇是**语义撞上的**还是**我真的写过这几个字**。

**词面层的老 bug**：`keywordHits` 的 `scopes` 参数传 `null` 时直接读 `.length` 抛 `TypeError`，被上层 `catch` 吞成「没有词面命中」——`/test` 的词面补漏因此静默失效很久。现在 `scopes` 容错为「全范围」，并把 `keywordHits` 从 `apiRoute` 闭包提到模块级（`pre-step` 也能用）。

**打点去重（从源头压噪）**：`/beacon` 现在按 `bundle rev` 去重——同一个 `rev` 的 `factory/apply/registered` 只记第一条，重复上报返回 `{recorded:false, skipped:'duplicate', rev}`。`rev` 取自 `ctx.get('clientModules').composed.rev`；服务不可用时退化成「同一 stage 5 分钟内不重复」。配合每 50 次触发的 `pruneLog()`（>3000 行只丢 beacon），日志不会再把召回行挤出读取窗口。

**日志瘦身**：`client-beacon` 每次 HMR 刷三条，攒到几千行会把召回行挤出读取窗口，面板就显示「累计召回 0」。现在 `writeLog` 每 50 次触发一次瘦身：超过 3000 行时**只丢 beacon**（保留最近 200 条排障用），召回/mounted 一条不动；`readLog` 上限从 500 提到 5000。

**没有明细也要报次数**：命中率需要 `items[]`，老日志没有。这时卡片显示 `—`，但 note 会写「近 7 天召回 20 次，但旧日志没记明细，算不出命中率」——不能因为算不出比率，就把「召回过 20 次」一起藏掉。

**日用量汇总**：每成功召回一次，`state.json` 里 `usage` 会累加当天一行 `{recalls, injected, chars}`（保留 60 天）。日志是明细、会被轮转清理，**清一次「累计召回」就归零**——汇总不会。`/status` 的 `stats.source` 会标 `log` 还是 `rollup`，面板在累计数来自汇总时显示「含历史汇总」。

`chars` 记的是「注入内容一共多少字」，不是「被打开几篇」——后者只能从日志明细里 `items[].used` 数出来，所以命中率始终以日志为准。

**本周条**：今天页四张卡下面一行 `本周 212 条 · 3 勾掉 · 15 新欠 · 从周一起算（11-16）`。周一是本机时区的自然周（`getDay()+6)%7`），只统计这一周内的日记；「新欠」用警告色——**单看「今天」看不出趋势，一周的账才好判断这周是在还债还是又欠了一笔**。

**试出来的参数能带走**：`临时放宽` 旁边有「变成配置」，展开给一段可直接粘贴的 YAML——只列**和当前配置不同**的项（全写会把默认值固化成显式配置，默认变了反而不跟随），文件路径由宿主解析（`/status` 的 `profileFile`，按 profile 的 `package.json` 里有没有本插件来认，不写死 `desktop`）。

**不自动改你的配置**：App 正在跑，替人写 profile 文件写错会静默失效（面板看着正常、参数没生效），所以只给片段 + 复制按钮，什么时候落盘由人决定。

**「还没有记录」要说明为什么**：召回统计卡为 0 时，面板会补一句「日志里已有 N 条记录（最早 …），但召回记录被清空过」——日志被轮转/清理后，`0` 和「从没工作过」长得一样。

**摘要也是旋钮**：`临时放宽` 多了第三排 `摘要[默认|180|120]`。同一份预算下把摘要收短，能装进更多篇——`/test` 会算好对比写在被挡掉那块：`摘到 120 字的话，能多进 5 篇`（返回体 `alt: {excerptChars, picked, current}`，算不出来就是 `null`）。真机实测：「止损线怎么定」默认注入 7 篇；把摘要收到 120 字 → 12 篇全进，一篇不用挡。**加预算 vs 收摘要，两个旋钮要能一起比。**

**「再加多少字就够」**：被预算挡掉时，那一行会写 `再多给 2713 字，这 5 篇都能进来` + 一个 `按这个数字再试` 按钮。`/test` 的返回体里带 `need: {rows, extraChars, budgetChars}`（`budgetChars` = 这次已用 + 补上被挡掉的），预算够时 `need: null`。**给目标值，别让人猜**。

**临时放宽**：召回页「试一下」下面一行 `临时放宽 阈值[默认|0.08|0.05|全都要] 预算[默认|2400|3200]`。只在这一次生效，**不写配置**；放宽后「被挡掉的」会少几条、注入几条立刻变。判断「该不该改 config」之前先能试。

**被挡掉的也看得见**：召回页「试一下」在注入列表下面多一行 `▸ 被挡掉的 N 篇`（分数不够 a · 超预算 b），点开逐条列出并标明原因，条目可点开原文。**只显示「注入了什么」，人会以为「没召回」=「没有」**；记忆偏保守这件事必须能量出来。

**「试一下」给的是过程，不是结果**：跑完列出这次的全部候选（标题 / 路径 / 摘要 / 分数），并标出谁会被真正注入（✓）、谁因为分数低于阈值被丢、谁因为 `maxChars` 预算被丢，顶部一行写清参数（模式 · 阈值 · 取前几篇 · 预算多少字）和汇总（候选 N · 注入 P · 分数不够 X · 超预算 Y · 耗时）。为什么要有：自动召回是黑盒，人看到「这都被捞回来了？」时得能自己查账。**最近召回可以点开**：每行是「时间 + 当时的提问 + 召回了 N 篇」，点一下展开就是当时召回的每一篇（标题 + 分数，再点跳原文）。**展开后还会显示这一轮的密度**：`本轮注入 1180 / 1600 字` + 一根进度条，每条命中带它占的字数，被 `excerptChars` 截过的标「截断」——「记忆占了多少上下文」这件事得能量出来，不然永远只能凭感觉。新日志带 `items`（路径+标题+分数+chars+truncated）与 `budget/used`，老日志只有标题，那时行不可展开、也不显示密度。**行头还会显示「用上 N」**：面板里打开某一篇时会打一个点（`POST /used`，记进 `.dsh/personal-memory/state.json` 的 `used`，上限 200 条），`/status` 把「打开时间晚于那次召回时间」的那几篇标成用过——这是召回有没有用唯一的自证信号，判断刻意保守（只比时间，不猜会话归属）。

顶部还有：工作区路径、笔记/天数/条数/未完成数的状态条、刷新（强制重扫目录）、**跳转**（`⌘K`）、**+ 新建笔记**、**速记**。

**⌘K 快速跳转**：任何页签下按 `⌘K`（Windows/Linux 是 `Ctrl+K`）都会浮出输入框，边打边筛全部笔记（标题 + 路径，`index.md` 往后排），`↑↓` 选、`Enter` 打开 —— 打开的文档会按它所属的 scope 自动切到对应页签。候选列表最上面先是六个页签（今天/个人记忆/时间长河/未完成/检索/召回，accent 色 + 「页签」副标题），没输字时也能直接跳页；手机上没键盘，这是唯一的「去哪」。`Esc` 关闭。

**星标**：阅读器右上角那颗星只管「常用」，不动笔记内容 —— 状态落在工作区的 `.dsh/personal-memory/state.json`（和笔记分开，删掉也不丢笔记）。星标过的那几篇在左栏最前面单独成组。

**project 也在树里**：「个人记忆」页的左栏现在同时列 `personal/` 和 `project/`（项目根单独一组，排在 personal 之后）。项目 README 本来就在检索索引里，能搜到也该点得进去。`memory/index.md` 和日记模板这类「不属于某一天」的文件，挂在「时间长河」页顶部，不混进时间线。

**上一篇 / 下一篇**：阅读器右上角一对 `‹ ›`，按当前这一页的顺序走（个人记忆按左栏树的顺序、时间长河按日期倒序），键盘 `[` `]` 同样可用；在输入框里打字时不会劫持。**读一串笔记时手不用回左栏。**

**今天勾掉的那些**：一直是只显示欠的——人看久了会以为今天什么都没干。所以「今天该做的」下面留一行 `✓ 今天勾掉 N 条`，点开是划线的小清单（数据来自当天日记里的 `- [x]`，`/timeline` 每天带 `doneItems`）。清单里每一条都能点——打开那天的日记并滚到它所在的小节，做完的事也能回到现场。

**今天没写的时候**：首屏会给一块提示条（左边一道强调色的竖线）——「今天还没写」+ 两个动作：写今天的第一条 / 记一件要做的事。今天已经写过就不出现，不占版面。

**打开就有东西看**：点侧栏图标进来，`App` 会自动落一篇 —— 在「个人记忆」页开 `personal/关于我.md`，在「时间长河」/「未完成」页开最近一天的日记，在「检索」「召回」页不自动开（那里没有阅读区）。切页签时如果当前选中的文档不属于这一页（比如从日记切回个人记忆），会重新落到该页的默认位置，不会出现「左边列表换了、右边还是旧文档」。

**速记**：一个弹窗，选分节（产出 / 判断 / 未完成 / 备忘），写一句话，`⌘↩` 提交。它**只追加**到当天的 `memory/YYYY/MM/YYYY-MM-DD.md`；文件不存在就按模板新建；写完按配置自动触发一次 contextdb 热重建（`POST /reindex`），这样下一轮召回就能查到。

**勾错了能退**：勾掉之后的提示条上带「撤销」—— 它调的是同一个逐行写回接口（反向 `done`），所以撤销同样会校验行号和原文，不会瞎改。

**今天页直接加待办**：「今天该做的」列表下面有一行输入框，回车就往今天的日记「未完成」里追加一条 `- [ ]`，不用先开速记弹窗再选分节。散步回来想起一件事，就应该是这个成本。

**勾掉待办**：未完成页和日记正文里的 `- [ ]` 都能直接点。写回是**逐行、带校验**的：面板把行号 + 那一行的前 40 个字一起发给宿主，宿主只在这行确实还是那条待办、内容也对得上时才改（否则返回 400 让你刷新）。所以误点、旧数据、并发改动都不会把日记写坏 —— 它只会拒绝，然后什么都不做。

**改字**：阅读器右上角有「编辑」。点开就把正文换成一个等宽字体的编辑器（默认打开磁盘上的原文），`⌘S` 保存、`Esc` 取消；有未保存改动时「取消」要点两次才丢。保存是**带指纹的**：面板把打开时那篇内容的 sha1 短哈希一起发上去，宿主发现磁盘上已经变了就返回 409 而不是覆盖 —— 所以「另一台设备改过同一篇」不会互相抹掉。保存成功后列表、状态条、相关笔记一起刷新。

**新建笔记**：顶部「+ 新建笔记」→ 填标题、选目录（只列 `personal/` 下已存在的目录，避免手打路径），`⌘↩`/按钮提交。宿主按工作区约定生成骨架（`# 标题` + `更新:<今天>` + `来源:面板新建`，正文留空），重名自动加 `-2`、`-3`；建完**直接进编辑态**，接着写正文。日记不在这里建 —— 日记靠「速记」按日期生成，日期目录不能手填。

**窄屏（手机）**：宽度小于 820px 时，列表与阅读器不再并排 —— 先看列表，点一篇才整屏进正文，正文顶部有「‹ 返回列表」。手机上和桌面上是同一份代码，判断只看视口宽度（`useNarrow()` + 一段 CSS 媒体查询），没有第二套 UI。

设置页里也有一个「个人记忆」分区，只读展示当前配置。

### 挪过几次：反复改期的，通常不是排期问题

未完成页的条目上会挂一个 `挪过 N 次` 的徽标（挪过 2 次以上才显示），并多出一枚「老是往后挪的」筛选；tooltip 写着「从 MM-DD 起一直在往后挪——不是没时间，是这件事本身还没定下来」。

链条存在 `state.json` 的 `moved` 里，key 是**待办正文的前 60 字**（不是行号）：挪到另一天、换一节，都还是同一条。每条链只留最近 6 步，全局最多 300 条。`/timeline` 为每条待办补 `movedCount` / `movedFrom` / `movedTo`，前端不做额外请求。

只挪过 1 次不标：临时改期是正常调度。标到第 2 次，是在说「这条已经被你推过两次了」，那才值得停下来问一句为什么。

「最近查过」也记这个开关：历史行会显示「… · 只看待办」，点回去**连带把开关打开**——否则恢复的是同一个词、却不是同一屏。

迁移是**可数的、而且能显式落盘**的：`GET /state/export` 除了 `v` / `fileVersion`，还报 `migration: { from, migrated: [{table, fixed}], fixed }`——「这次读进来把 9 条 v0 的旧格式补成了新形状（检索历史 6 · 在等什么 2 · 折叠偏好 1）」，界面上就这么写，旁边一个「现在写回文件」按钮走 `POST /state/migrate`。

不落盘的迁移是个隐患：只要没人再写状态，每次读都要重迁一遍，而且永远没人知道迁过。

`state.json` 现在带版本号（当前 `v: 2`）。字段形状变过一次（`wait` 从字符串升级成 `{kind, at}`），当时是靠 `sanitizeWait` 顺手兼容的——那种隐式兼容散在八个 sanitize 里，改一个字段要翻八处。现在：

- 读的时候先过 `migrateState()`：`v0` 的「queries 是字符串数组」「wait 是字符串」「ui 直接平铺布尔」都在这里一次性迁成当前形状
- 写的时候一律打上 `v`，`/state/export` 同时报 `v` 与 `fileVersion`，两者不一致就在界面上写「读的时候已就地迁移」
- 迁移只负责形状，字段合法性仍交给各表的 sanitize——两件事分开，才不会被互相掩盖

### 「看一眼就走」的目录页：把路过变成一条线索

目录页被点开、几秒就关，通常不是"看过没动"，而是**我想找的东西没写在这个索引里**。这时候要的不是"补一句"，是记下"我在找什么"。

所以 `kind === 'index'` 且 `0 < dwell < 10s` 的行会多一个「记一条线索」：输入"你想在这页找到什么"，直接以 `- 想找：…` 补到这页末尾（`POST /append`）。

`/append` 只做一件事，但三道锁都在：`safeDocPath` 路径白名单（跟 `/save` 同一把）、可选 `hash` 并发校验（409）、**同一句不重复写**（返回 `appended: false`）。它不新建写入口径——面板上所有写操作仍然只有这几种。

### 命中上方先给「三个数」

检索现在有四路命中，混排在一张表里。人其实想先知道的是**比例**：这一屏里有多少是我写过的正文、多少是待办状态、多少是「想找但没找到」。

所以命中上方除了「N 篇命中 · X ms」，还有三个可点的数：**笔记 2 · 待办 1 · 线索 1**（为 0 的不显示）。点一下就是只看那一类：`only=note` 会关掉待办与线索两路、只留向量 + 词面；`only=state` / `only=clue` 同理，单选，再点一次取消。

### ⌘K 的最后一行是「去搜内容」

⌘K 只匹配**标题与路径**。标题里没有，不等于正文里没有——所以输入任何词时，候选列表末尾多一行：**用「这个词」搜内容**（Enter 直接进检索页）。

不顺手的两个细节都处理了：这一行永远在最后（不抢标题命中的位置），但如果一个标题都没命中，它就是唯一一行、默认选中，回车即可。

### 搜不到的时候，给「记一条线索」

语义检索几乎总能捞回点什么，所以「零命中」很少见——但一旦真的零命中，那一屏只说「换个说法试试」，等于把最该留痕的时刻打发走了。

现在零命中时多一段：**搜不到，说明这里缺一块**，下面一个「记一条线索」（预填当前的搜索词）→ 直接写进某个索引页的 `- 想找：…`，下次搜同一句它自己会浮出来。

这跟「翻过没动」的「记一条线索」共用同一个表单（`clueForm()`），区别只是从哪触发：一个从「路过但没懂」，一个从「搜了但没有」。

### 「只看某一类」是单选，不是两个开关

命中现在有四路（`vector` / `keyword` / `state` / `clue`）。混在一张表里，人想「专门看看我还缺什么」就得自己筛，所以检索页给了两个开关：**只看待办**、**只看线索**。

它们是**互斥的**（`onlyKind: '' | 'state' | 'clue'`）：两个都亮等于「什么都要」，那是默认态而不是筛选态。开启任一个时，范围 chip 会变淡并禁用（待办只活在 `memory/`，线索也基本写在索引页），避免「chip 显示在筛，其实没筛」。

`/search?only=clue` 与 `?only=state` 语义一致：不跑向量检索、不跑词面补漏，只出对应那一路。

### 线索本身也进检索

`- 想找：X` 这一行的意思是「我搜过、没搜到」——所以搜同一句话时，它自己就该出现，标 `线索`，摘要写成「想找：…」。

它和笔记命中混排会误导（会以为有人写过），所以视觉上分开：徽标不同、摘要前缀不同。`/search` 的 `via` 于是有四种：`vector` / `keyword` / `state`（待办）/ `clue`（线索）。

### 「该去哪补」可以直接点

知道「缺的是没人写过」还不够，得能一键开始：

| 类型 | 按钮 | 动作 |
|---|---|---|
| 想知道答案 | 写一篇 | 打开新建笔记，目录预填这页所在目录 |
| 想确认结论 | 去核对 | 切到检索页并带着这句话跑一次 |
| 想找回原话 | 找回原话 | 同上 |

线索行右侧多一个按钮，不新增任何写入路径——只是把「你接下来要干的事」提前一步。

### 线索分三类想吃的东西

同一句「想找：止损线怎么定」，可能是三件不同的事：

| 类型 | 缺的是 | 该怎么补 |
|---|---|---|
| 想知道答案（`find`，默认） | 还没人写过 | 补索引或补一篇 |
| 想确认结论（`check`） | 当时写了什么、对不对 | 翻旧结论核对 |
| 想找回原话（`cite`） | 原话在哪一句 | 翻日记找出处 |

「+ 记一条」时选一个 chip；行里在第二行（路径行）前面显示类型。**三类不分开，列表只能告诉你「我还缺东西」，告诉不了「我该去哪补」。**

顺手修掉一个存储缺陷：线索原来按「整页一条」存，同一页记第二条会覆盖第一条的类型与时间。现在按 **页 + 正文**建档（`path\u0000text`），老格式（整页一条）仍能读。

### 线索视图自己加「+ 记一条」

原来只有「翻过没动」的目录页才能补线索——想到一个缺口，得先路过某页才顺手记。多一层路，就少一次记录。

现在线索视图标题右边有「+ 记一条」：输入想找的东西 → 选一个目录页（`/clues` 一并返回 `indexPages`，personal 优先）→ 补到该页末尾。写入走同一个 `POST /append`，所以去重、指纹、行数上限都照旧生效。

### 悬着的线索也有「悬了多久」

解决过的线索能看到时间，悬着的原来只有一句「还悬着」。所以每条线索再带 `clueAt` / `ageDays`：

- `ageDays >= 3` 才显示「悬了 N 天」（今天刚记的不刺痛眼睛）
- **没有记录就给 `null`，不拿文件 mtime 冒充**——mtime 说明的是「这页最后改过」，不是「这条等了多少天」。手写进文件的老线索就属于这一类
- 列表排序：还悬着的优先，同一档里「悬得越久越靠前」

### 最近解决的留一周

解决过的线索默认不该再占位置，但「解决完就从列表里消失」有个副作用：**看不出我最近在补哪些缺口**。

所以 `/clues` 额外返回 `recent`：`resolved` 表里最近 7 天、最多 10 条，带「今天 / N 天前」。一周后自然滚出去——不需要清理机制，需要的是「给可见性一个到期日」。

### 线索可以「解决了」

指纹只能抓「这页改过」，抓不到「我找到了，只是写在别处」。所以线索还有第二个状态位：**我自己标的已解决**（`POST /clue/resolve`，key 是线索正文，不是行号——行号会随增删漂移）。

两个状态位是独立的：

| | 这页改过 | 我标了解决 | 显示 |
|---|---|---|---|
| 还没处理 | ✗ | ✗ | 还悬着 |
| 写在别处 | ✗ | ✓ | 已补进正文（标了） |
| 顺手改了 | ✓ | ✗ | 已补进正文（改过） |
| 都算处理过 | ✓ | ✓ | 已补进正文 |

否则「改过」会把「我已经知道了」覆盖掉——**「发生过什么」和「我怎么判断」不能挤在一个字段里**。

### 「线索」：把所有想找的东西收在一处

单看一行 `- 想找：…` 看不出名堂；攒起来才看得出「我反复在找什么」——那通常说明索引缺了一块。

`GET /clues` 会扫全库所有 `- 想找：…` 行，每条给三样东西：**出处（路径 + 行号）、状态、时间**。

状态只有两档，判据是**文件指纹**而不是时间戳：

| 状态 | 判据 | 含义 |
|---|---|---|
| 还悬着 | 当前文件指纹 == 补线索时记下的指纹 | 补完没再动过这页，那条线索还没落进正文 |
| 已补进正文 | 指纹变了 | 之后又改过这页，当时想找的东西大概率已经写进去了 |

用指纹而不是 `clue.at + 60s`：时间戳在同一秒内多次写盘时分不出来，而且 60 秒这个阈值是我编的——**判据要能解释「改了一次就算处理」，不该依赖猜的秒数**。

### 补过线索的目录页，一周内安静

「记一条线索」写完之后，这一页**还会**出现在「翻过没动」里——因为它的 `usedAt` 没变、mtime 也只在补线索时动一下。列表于是变成「我处理过了，它还在催」。

所以 `POST /append` 在补的是 `- 想找：…` 时，往 `state.json` 里记一条 `clues[路径] = {at, text}`；`/visited` 遇到「clue.at ≥ 本次打开时间」且「距今 < 7 天」的，直接跳过。

- 只静默 7 天，不是永久：一周后还这样，说明那条线索没被消化
- 静默期按 `clue.at` 算，不按 mtime——补完线索又读了这页，`clue.at < 本次打开`，提醒会回来

### 「翻过没动」现在知道你是"看了一眼"还是"读了两分钟"

原来打点只记「打开过」。可同样是打开过，「点开就走」和「停下来读了 3 分钟」是两件事——前者说明入口写得不清楚，后者才是"看完没动手"。

所以 `used` 表从 `{路径: 时间戳}` 升级成 `{路径: {at, dwell}}`：

- **客户端**：`openDoc()` 切到下一篇时，把上一篇的 `Date.now() - 打开时刻` 报一次（`dwell >= 1500ms` 才报，太短的来回切换不算阅读）。`POST /used {path, dwell}`。
- **宿主**：`dwell` 取**历史最大值**（`Math.max(prev.dwell, 本次)`）。传 0 或省略不会把已有的时长清掉——「这次没测到」不等于「上次没读过」。
- **面板**：`< 10 秒` 说「看一眼就走」，`< 60 秒` 说「停了 N 秒」，再长说「读了 N 分钟」。**没测到（`dwell` 为 0）就整段不写**，不编「看一眼就走」。

老格式（数值时间戳）照读不误，读的时候就地迁成 `{at, dwell: 0}`——见 `sanitizeUsed`。

### 「翻过没动」里，目录页不是正文页

`stock/index.md`、`work/index.md` 这种目录页被打开，通常只是「进去找东西」——它跟「看了一篇正文、当时觉得有用、后来没回来」不是一回事。所以 `/visited` 每行多带一个 `kind`：`index`（`index` / `README`）或 `note`。

面板上：目录页前面标「目录」，右边那个按钮也从「补一句」改成「加一条」——对索引页说「补一句」本来就不合适。

判断用的是 `doc.file`，注意它**已经没有 `.md` 后缀**（`basename(abs, '.md')`），所以正则是 `^(index|readme)$`，写成 `\.md$` 会一条都匹配不上。

### ⌘K 里排在最前的是「最近看过」

按修改时间找东西，假设的是「我刚改的那篇就是我要的」；实际上多数时候想跳回去的是**刚看过的那篇**——看的时候可能一个字都没改。

所以空查询时，⌘K 的顺序是：六个页签 → 最近看过的 5 篇（带「今天看过 / 2 天前看过」）→ 全部笔记（index 靠后、按 mtime 降序）。输入关键词时「最近看过」自动收起，因为那时你是在找，不是在回去。

0 天前、1 天前这种说法不出现：`今天看过` / `昨天看过`，再往前才是「N 天前看过」。

### 实验记录：跑过的对照留在磁盘上

「换个说法」和「四个旋钮」跑完就散了——想知道「上周那条查询当时为什么只进 3 篇」，只能重跑一遍，而工作区已经变了，重跑出来的不是当年那个结果。

所以每跑一次就往 `.dsh/personal-memory/experiments.jsonl` 追加一行（`{at, kind, query, rows[]}`），召回页下面列最近 12 次，点任意一行就把**那次的查询和结果**重新铺到上面（是回看，不是重算——数字是当时的）。

两条设计取舍：

- **单独一个 jsonl，不塞进 `state.json`**：它是流水、会长，不该让每次读状态都解析它
- **保留 200 条，超出丢弃最旧**：实验记录的用途是「回溯最近在调什么」，不是档案

### 四个旋钮一起看：一次搞清楚该动哪个

「临时放宽」是逐个试：改阈值试一次、改回、改预算再试一次——三次下来人只记得最后一次。但阈值、预算、摘要长度这三个旋钮互相耦合（摘要短了，预算就够用；预算大了，低分的也进得来），必须**同时**摆出来才看得出谁是瓶颈。

所以「换个说法再试」下面再加一个「四个旋钮一起看」：对当前这句话跑五套配置，并排给出 **注入数 / 候选数 · 分数不够 · 超预算 · 首位分**：

| 配置 | 改了什么 |
|---|---|
| 默认 | 不动 |
| 阈值 0.05 | 只降阈值 |
| 预算 2400 | 只加预算 |
| 摘要 120 | 只缩短摘要 |
| 三样一起 | 全部放开 |

五套是 **默认 + 每个旋钮单独动 + 全开**，不是全组合（8 × 4 × 3 = 96 次请求没人等得起）。点任意一行就按那套参数重跑「试一下」。

实测（`钧达的止损线怎么定？`）：默认注入 10/12 篇、超预算 2；只降阈值毫无变化（低分本来就是 0）；**只加预算或只缩短摘要，都能把 12 篇全放进来**。结论直接摆在那里——这条查询的瓶颈是预算，不是相关性。

### 翻过但没动：`GET /visited`

检索页多了一个开关「翻过没动」：列出**打开过、之后一直没再改过**的笔记。判断规则在宿主侧：

- 取 `state.json` 的 `used` 表（`POST /used` 打点）
- 只留 `used[path] > 0` 的
- `mtimeMs >= usedAt - 60000` 的**排除掉**——打开后一分钟内又改过，算「打开时顺手改了」，不算「翻了没动」

每行给两个时间：`看过 N 天前 · 改于 M 天前`。这类笔记通常意味着「当时觉得有用、后来忘了」，用户自己未必说得出来，但列表能。

每行右侧还有「补一句」：**直接进编辑态、光标落在文末**（`editAt = EDIT_AT_END` 哨兵值）。列表只说明「我看过没动」，要动就得有一步——补记是接着写，不是改中间，所以不定位具体句子，直接落末行。

这条也是「看到」和「做到」之间的距离问题：只给列表，人看完还是得自己想办法；给一个动作，成本降到一次点击。

### 两条时间线：改于哪天 vs 看于哪天

命中行上原来只有一个时间徽标（改于 3 天前）。但「这篇最近改过」和「我上次为它停下来过」是两条不同的线：

- **改于**（`mtimeMs`）：文件什么时候被动过
- **看过**（`usedAt`）：我在面板里打开过它，来自 `POST /used` 打点，存在 `state.json` 的 `used` 表

两个都显示：改于用灰底、看过用强调色（「看过 · 今天」）。没打开过的只显示改于，不写「从没看过」——**没有记录不等于没发生**。

### 换个说法再试：措辞怎么改变召回

同一句话，语序、疑问词、有没有前后文，召回结果都不一样——但只看「这次挑中了什么」，永远不知道是「记忆里没有」还是「我的问法不对」。所以「试一下」旁边多一个「换个说法再试」：把当前输入拆成最多三种说法，各打一次 `/test`，并排给出**注入数 / 候选数 · 首位分 · 首位标题**，点任意一行就用那个说法重跑，看完整过程。

三种说法不做同义词猜测（猜错比不猜更误导），只做机械变换：

| 说法 | 变换 |
|---|---|
| 原话 | 原样 |
| 去掉疑问词 | 去掉「怎么/如何/是否/为什么…」与句末标点 |
| 只留实词 | 中文没有空格，按片段剜掉疑问词与虚词（的/了/呢/吧/吗）再压缩空白 |
| 补上下文 | 前面加一句「我在笔记里写过：」——同义改写里唯一不改变意图的那种 |

规则与面板里的 `phraseVariants()` 是**同一份**，`preview.mjs` 也从 `__parts` 里拿它（截图不能出现「面板不会这么拆」的假象）。

### 面板自己的状态：看得见、清得掉

`state.json` 攒了检索历史、星标、折叠偏好、用过的笔记、在等什么、下一步、改期链、日用量——全是隐性资产。召回页底部多一块「面板自己的状态」：

- `GET /state/export` 给出每张表几条、文件多大、什么时候改的，以及完整 json（可整块复制走）
- `POST /state/clear` 按表清空，**要带 `confirm: true`**，表名不在白名单（`queries / stars / ui / used / wait / next / moved / usage`）直接 400；清一张不碰其他张
- 界面上「清空」第一次点只把按钮变成「真的清掉？」，第二次才执行——删除不靠比手速

这块的意义不是「功能齐全」，是让这些数据**可被看见、可被放弃**：一份看不见又删不掉的状态文件，最后只会变成不敢动它的理由。

### 「只看待办」：状态命中要能单独看

状态命中混在笔记命中里时，想专门回答「我还在等什么」得自己扫每一行。检索栏多一个 `只看待办` 开关：打开后只走状态表这一路（`only=state`），`mode` 标成 `state`，笔记命中一条不回来。

打开时三个范围 chip 会**变淡并禁用**——待办只活在 `memory/` 里，那三个 chip 此刻不成立；与其让它们看着能点，不如明说「这时候范围固定」。没命中时文案也不是「没找到」，而是「没有匹配的待办。换一句话，或者取消「只看待办」」，因为这时人该做的是换条件，不是放弃。

### 待办状态也进检索

`下一步` / `在等什么` / `改期理由` 都存在 `.dsh/personal-memory/state.json` 里，不在任何 `.md` 正文里。但它们是**我脑子里正在转的事**——搜「对账表」时，如果只翻笔记正文，那些「等对账表」的待办就永远搜不到。

所以 `/search` 里多加一路：按 query 去匹配 `next` / `wait` / `moved` 三张表的**待办正文和值**，命中的行标 `via: "state"`，标题写成「下一步 · 2026-11-20」，摘要写「待办：<原文> — <下一步/等待/理由>」。点开仍然落到那天日记的对应小节（复用检索锚点）。

两个约束：① `next` 的值也算命中面（搜「对账」能搜到「等对账表」的待办），但摘要里一定带着待办原文，避免「搜到了却不知道是哪条」；② 限了 `scope=personal` 之类就不掺进来——待办只存在于 `memory/`，越界就是噪声。

### 「变成行动」顺带排进某一天

复查带里点「变成行动」，先问一句「下一步具体做什么」；填完**不用再单独去挪**——输入框右边就是两个落点：`排到明天` / `排到周一`。

点哪一个都做同一件事：把那句话记进 `next` 表（行上会留一行「下一步 · …」），同时把这条待办挪到那天（落进那天日记的「未完成」，理由字段就是这个下一步）。一个动作做完两件事，是因为这两件事在脑子里本来就是一件：「我打算这么做」和「我哪天做」分开填，人只会填前一半。

### 「为什么挪」：一句话，攒出来就是判断

**第二次**点「明天 / 下周一」时，行上会展开一个小输入框：「再挪一次，顺手记一句为什么」。回车 → 记下并挪过去；点「不写了，直接挪」→ 照样挪，只是链上那一步没有理由。第一次改期不问——正常调度不该被提醒。

每个理由跟着那一步进 `moved` 链（最长 80 字，空白会被压掉）。点一下行上的「挪过 N 次」，就地展开整条链：

```
这条一直在往后挪
11-20 → 11-21      （当时没写为什么）
11-21 → 11-22      等三季报出来再说
```

没写理由的那步**如实留白**，不补「未记录原因」之类的假话——留白本身就是信息：那几次你只是把它推走了，没想。攒到第三四次，一眼就能看出是「一直在等外部条件」还是「自己没想清要不要做」。

## 为什么是整页，不是浮层

第一版做的是右下角 460px 浮层。实际用下来，读一篇 200 行的日记要在一个小窗口里滚三屏，等于没做。DSH 的 slot 树里 `main` 是 keyed 的整页面板槽，`sidebar.panellist` 是侧栏入口列表 —— 在两边注册同一个 id 就行：

```js
slots.inject('sidebar.panellist', () => slots.register({ name: 'sidebar.panellist', id: 'personal-memory', order: -2, label: () => t('nav') }, PanelIcon))
slots.inject('main', () => slots.register({ name: 'main', key: 'personal-memory' }, (pageProps) => h(App, { ...pageProps, t })))
```

## 设计上的几个约束

- **不引入任何第三方前端依赖**。client 半只 `require('react')`（宿主模块表里就有）；markdown 渲染是自己写的 200 行：标题、段落、列表、`- [ ]` 待办、表格、引用、代码块、行内粗体/代码/链接。够读笔记，不值得为此背一个依赖。
- **样式全部用主题 token**（`--dsw-alias-*`），不写死颜色，深色/浅色主题自动跟着走。
- **写操作只有三种，且都只碰单行/单篇**：速记（只 append 一行）、勾待办（带行号+文本校验，只改那一行的 `[ ]`）、保存笔记（带内容哈希，冲突就 409 不覆盖）、新建笔记（`wx` 独占创建，重名自动加序号）。**没有删除**：删笔记该由人决定，不由浏览面板代劳。
- **路径白名单**。所有路径都过一个校验：拒绝 `..`、必须以 `personal|memory|project` 开头且以 `.md` 结尾，解析后的绝对路径必须还在工作区内。读和写用的是同一个函数，没有「只读宽松、写入严格」的缝。
- **工作区是显式解析出来的**，不靠 `process.cwd()`。宿主进程的 cwd 可能是任何地方，所以依次尝试：配置项 `workspace` → `DSH_PERSONAL_MEMORY_WORKSPACE`/`DSH_WORKSPACE` 环境变量 → `workingDirectory` 服务 → `workspaceRegistry` 里的工作区 → 从这些候选向上找同时含 `personal/` 与 `memory/` 的目录。
- **不用 `shell.overlay`**。浮层留给真正临时的东西。

## 自动召回

- 挂在 `agent/pre-step`，每步只处理一次；同一用户消息不重复、同一文档一次会话只注入一次（召回块末尾带 `<!--pm-ids:-->` 标记）。
- 子代理跳过；短于 `minQueryChars`（默认 6 字）或以 `/`、`!` 开头（斜杠命令）跳过。
- 注入内容明确标注「不是用户发言」，并附原文相对路径。
- 检索失败、超时、ctx-server 没起来：静默放过，绝不挡住对话。

**为什么不挂 systemPrompt**：`systemPrompt.section` 拿到的 `AssembleContext` 只有 `{ scope, signal }`，读不到用户这条消息的文本 —— 没有文本就没有查询。`agent/pre-step` 能看到即将进入这一步的 `messages`，也能返回替换后的消息列表。

**`decision.messages` 只是这一步新进来的消息**，不是整段历史。所以「谁在说话」只能靠 `source.kind` 分辨：

| `source.kind` | 内容 |
|---|---|
| `user` | 用户真正打的字 |
| `time-context` / `runtime-context` / `agent-instructions` / `skill-catalog` / `model-selection` | 每轮由 harness 合成的快照 |
| `plugin:<name>` | 插件（含本插件）注入的块 |

只有 `user` 该拿去当查询。

### 知识库体检：为什么面板要管这件事

个人记忆面板最容易烂的地方不是代码，是**内容**：一篇笔记忘了写 `更新:`、新建的目录没进 index、改名之后索引里的链接还在指旧名字。这些不会报错，只会让「翻得到」慢慢变成「翻不到」。

所以面板的「个人记忆」页顶部有一条体检：

- 没问题时只占一行小字：`✓ 体检通过 · 36 篇笔记都带着更新/来源，也都在索引里`
- 有问题时列出来（最多 3 条 + 「还有 N 条」）：`P0 死链 → desk/gone.md`、`P1 事件日历.md 缺「更新:」`，点一条直接打开那篇

判据和 `.dsh/skills/kb-audit` 用的是同一套，只是搬到了宿主里（`GET /audit`）：

| 检查 | 级别 | 为什么 |
|---|---|---|
| index 里的死链 | P0 | 索引说「有」，点进去没有——比没有更坏 |
| 缺 `更新:` / `来源:` | P1 | 一条不知道什么时候、从哪来的结论，半年后不敢用 |
| 没被任何 index 引用 | P1 | 写了但没人能顺着目录找到 = 埋了 |
| 根目录裸文件 | P1 | `personal/` 顶层只该有 `index.md` / `AGENTS.md` / `关于我.md` |

几个实现上的取舍：

- **默认只看 `personal/`**。`memory/` 是日记，日记不该有 `更新:`（它本身就是按日子写的）；把日记算进体检，等于每天给自己制造 20 条假警报。
- **`AGENTS.md` 不要求元数据**。它是这个目录的规矩说明，不是一条知识。
- **目录链接不算死链**。`[2026-11](2026/11/)` 指向文件夹，检查时按目录存在性判断。
- **元数据允许出现在引用块/列表里**。历史笔记里 `> 更新：2026-11-13`、`` `更新: 2026-11-19` `` 都真实存在过，格式差异不该被算成「缺失」。
- **只在 `reload()` 拉一次**，文本走和检索同一份 `TEXT_CACHE`，不额外读盘。

体检之后我真的按它修了一轮：把 6 篇的元数据统一成 `更新:` / `来源:` 两行、给 `desk/lhb-seats.md` 和 5 篇 `desk/daily-notes` 补上索引引用、删掉一篇面板自己造的测试残留。修完 `/audit` 返回 `counts.total = 0`。

## HTTP 路由（host 半，挂在当前 DSH Web 服务上）

| 路由 | 说明 |
|---|---|
| `GET /personal-memory/status` | 工作区、配置、召回统计、笔记/天数/条目数、索引健康、最近日志（每条带 `items: [{path,title,score}]`，面板靠它点回原文） |
| `GET /personal-memory/tree?scope=personal,memory,project&refresh=1` | 扫描工作区，返回每篇的元信息（标题、大小、行数、摘要、`更新/来源`、日记结构） |
| `GET /personal-memory/doc?path=personal/关于我.md` | 单篇全文 + 标题目录 + 元信息（限 512 KB） |
| `GET /personal-memory/timeline?refresh=1` | 日记时间线：按天聚合，带每天的未完成条目（每条带 `line`，勾选要用） |
| `GET /personal-memory/search?q=&scope=&topK=&days=` | 混合检索：ctx-server 向量 + 本地词面（标题/路径/全文），返回 `mode: vector \| hybrid \| keyword-only`，命中项带 `via` 与 `literal` 标记；`days=N` 只留最近 N 天改过的（0=不限） |
| `POST /personal-memory/test` | 手动跑一次召回（不写进会话）。返回 `rows`（全部候选，含 `picked`/`drop`/`via`/`literal`）、`params`（`topK`/`fetchK`/`threshold`/`maxChars`/`mode`）、`dropped`（`{low,budget}`）；`hits` 只放会被注入的那几篇（兼容旧客户端） |
| `POST /personal-memory/reindex` | 热重建 contextdb 索引 |
| `POST /personal-memory/note` | 速记：追加到当天日记（只 append）。`{text, section?}` 记一条带时间的事；`{text, todo:true}` 直接往「未完成」加一条 `- [ ]`（不带时间前缀） |
| `POST /personal-memory/todo` | 勾/取消一条待办：`{path, line, done, expect}`，只改那一行 |
| `POST /personal-memory/todo/defer` | 改期：`{path, line, expect, to?}`（默认明天，也认 `monday`）。先往目标日记的「未完成」落一条同文的，成功了再删源行；已勾掉的、同一天的、文本对不上的都拒 400。返回 `moved`：这条被挪过的次数 |
| `POST /personal-memory/save` | 保存笔记：`{path, text, hash}`。hash 对不上（磁盘被改过）返回 409；正文超 512 KB 返回 400 |
| `POST /personal-memory/create` | 新建 personal 笔记：`{scope?, dir, title}`，按约定生成骨架，重名自动 `-2/-3` |
| `GET /personal-memory/state` | 面板自身的状态：最近查过的 query（最多 20 条）、星标路径 |
| `POST /personal-memory/ui` | 记折叠偏好（`{collapsed:{"month:2026-11":true}}`，按 key 合并、只收布尔、键名 ≤80 字）。跟工作区走，刷新页面不会又全展开 |
| `POST /personal-memory/star` | 星标/取消：`{path, on}`，只写 state.json，越界路径 403 |
| `GET /personal-memory/beacon?stage=` | 客户端存活打点（client 半启动时自己上报，写进日志） |
| `GET /personal-memory/debug/client` | 自省：client 模块图里有没有本插件、rev 是多少 |
| `GET /personal-memory/audit?scope=personal` | 知识库体检（只读）：缺 `更新:`/`来源:`、没被任何 index 引用的孤儿、index 里的死链、根目录裸文件。返回 `{items:[{level,path,issue,hint}], counts:{p0,p1,p2,total}, notes, topics}` |

`smoke-live.mjs` 证明的是另一件事：**代码真的装进去了**。本地全绿但宿主还在跑旧模块，这种「测试通过、用户看不见」的情况它抓过：`/doc` 的越界路径返回 500 而不是 403（而当时的本地断言写的就是 500）。

`check-props.mjs` 是补「中间层漏传」这个反复出现过的坑：症状是截图里那块空着、但代码本身没错。它静态对比「子组件读了哪些 `initialXxx`」与「App 渲染它时传了哪些」，漏传直接非零退出。加它的时候当场揪出 4 个组件共 7 个漏传（`initialTodoSort`、`initialWaitOnly`、`initialMovedOnly`、`initialHits`、`initialTestMeta`、`initialShowDropped`、`initialSnippetOpen`、`initialTrialHint`）。

还有一条**截图链路**（不是测试，是给人和给未来的自己看的）：

它复用 `harness.mjs` 的假运行时，把页面序列化成静态 HTML（自带 React 树→HTML 的序列化器），再用系统里的 Chrome 无头模式截图。检索页是异步 fetch，`settle()` 只看渲染是否稳定，所以带 `--search=` 时要「渲一次 → 等 400ms → 再渲」，否则截到的是空态；换页签/组件前必须 `reset()` 清 hook 状态，否则页签会粘在上一次。好处是**改样式不用重启 DSH、不用点开 GUI 就能看到真实的排版**；代价是主题 token 用的是预览里内置的一套近似值，真实颜色以宿主为准。

`smoke-render.mjs` 是这套里最值钱的一个：它不需要浏览器和 React，直接执行 `client.js` 拿到注册结果，再用真实数据（走真实 host 路由）把 `App` 和每个视图都渲染成元素树，断言「渲染不抛异常、字段对得上、列表真的有 31 条、待办真的有 37 条、相关笔记真的有 5 条、今天页落在 `pmp-today`、⌘K 有候选」。GUI 里出现空白 slot 的成本很高，这一步用来把它挡在前面。

**已确认在真实 GUI 里活着**：client 半启动时用相对路径打三个点（`GET /personal-memory/beacon?stage=factory|apply|registered`），日志里出现 `registered` 就说明侧栏入口、整页、设置分区都注册成功了。改完 client.js 存盘，HMR 会重载页面并重新打点 —— 比去翻 Electron 的缓存文件靠谱得多（缓存里搜字符串是搜不到的，V8 code cache 不保证把字面量落盘）。

**界面不出现的排查**：client 半的 boot 清单是 GUI 启动时扫描 package 的 `dsh.client` 声明生成的。装好插件之后才改 client 半，需要**刷新页面**；如果连 `dsh.client` 声明本身都是新加的，需要重启 DeepSeek Harness。host 半的重载只需要 `set_plugin` 一次。host 路由和自动召回不受影响，装好即生效。

## 改完代码怎么让它生效

- **client 半**：如果 `pnpm run dev:web` 正在跑，DSH 的 client HMR 会自己重载，保存 `client.js` 后日志里很快出现新的 `factory → apply → registered`（带新 `rev`）。**没跑 watcher 时不会推**——这时手动刷新页面（⌘R）即可，页面会按新 `rev` 重新取 bundle。判断有没有生效：`GET /debug/client` 的 `mentions.rev` 应等于日志里最后那条 beacon 的 `rev`；两者不等就是页面还没刷。
- **host 半**：不会自动重载。可用的方法是让 loader 重新应用这个条目：

  ```
  plugin_manager set_plugin { target: 'include:personal-memory', enabled: false }
  plugin_manager set_plugin { target: 'include:personal-memory', enabled: true }
  ```

- **前提**：这个条目必须是「可寻址」的，也就是 profile 的 `cordis.patch.yml` 里得有它的一行。由 profile `dsh.profile.bundles` 带进来、却不在 patch 文件里的条目，`plugin_manager` 会报 `unaddressable`，此时只能重启 App。补一行就够（`insert` 是安装时写的同款结构）：

  ```yaml
  - insert:
      - id: personal-memory
        name: dsh-personal-memory
  ```

  去掉 `config`，让它继续跟随 `DEFAULTS`；一旦在 patch 里写了 config，那个值就被固化成显式配置。
- **踩过的坑**：往 profile patch 里写一条「同 id、带 `name`、只有 `config`」的覆盖项，会把运行中的条目**摘掉且不重新挂载**（路由直接 404，客户端还在跑，面板一片空白）；改回去也不会自动恢复，必须用上面 `insert` 的形式重新插入。
